# Кредитный скоринг

Портфолио-проект по прогнозированию дефолта на момент кредитной заявки.
Источник данных — [Home Credit – Credit Risk Model Stability](https://www.kaggle.com/competitions/home-credit-credit-risk-model-stability/data).

## Подготовка данных

Проект использует Python 3.13 и uv. Выполняйте команды из корня репозитория.
Войдите в Kaggle и примите правила соревнования перед скачиванием.

```sh
uv sync --locked --group notebooks
mkdir -p data/raw
uvx kaggle competitions download -c home-credit-credit-risk-model-stability -p data/raw
unzip -n data/raw/home-credit-credit-risk-model-stability.zip 'parquet_files/train/train_base.parquet' 'parquet_files/train/train_static*.parquet' 'feature_definitions.csv' -d data/raw
```

Архив и исходные таблицы хранятся локально в `data/raw/`.

## Запуск

```sh
uv run --locked --group notebooks jupyter lab notebooks/01_eda.ipynb
uv run --locked train-baselines
```

Код проекта находится в пакете `src/credit_scoring/`, исследования — в
`notebooks/`. `pyproject.toml` описывает зависимости, `uv.lock` фиксирует
их версии. Группа `notebooks` добавляет зависимости для Jupyter.
Интерфейс Streamlit находится в `app/streamlit_app.py` и использует пакет
`credit_scoring` для оценки риска.

В ноутбуке проверяются покрытие при соединении таблиц, пропуски и доля
дефолтов по неделям. Скрипт обучает логистическую регрессию и CatBoost на
одинаковых признаках из `static_0`. В набор входят сумма и тип кредита,
доход, текущая задолженность и агрегаты кредитной истории. Список
зафиксирован в скрипте. Из входов исключены идентификатор кейса, дата и
номер недели, а также параметры выдачи с неоднозначным моментом доступности.

У LogReg заполнение числовых пропусков, стандартизация, кодирование категорий
и оценка коэффициентов объединены в `sklearn.Pipeline`. CatBoost использует
собственную обработку категорий и числовых пропусков. Пропуски категорий
для обеих моделей заменяются отдельным значением.

Первые 55 недель используются для обучения, следующие 18 зарезервированы
для будущей калибровки и выбора порога, последние 19 используются для оценки.
Настройки моделей заданы заранее. Скрипт сравнивает исходные вероятности
с константой, равной доле дефолтов на обучении. Горизонт наблюдения таргета
нужно подтвердить для имитации запуска на конкретную дату. Текущее разбиение
проверяет перенос на более поздние заявки.

## Результаты базовых моделей

Оценка на 203 345 кейсах с 26 мая по 5 октября 2020 года. Доля дефолтов
в этом периоде составила 2,19%. Обучение использовало 1 129 770 кейсов.

| Модель | ROC-AUC ↑ | AP ↑ | PR-AUC ↑ | Log loss ↓ | Brier ↓ | Средний прогноз |
|---|---:|---:|---:|---:|---:|---:|
| Константа по обучению | 0,50000 | 0,02188 | 0,51094* | 0,10688 | 0,02149 | 3,13% |
| Логистическая регрессия | 0,65698 | 0,04681 | 0,04671 | 0,10665 | 0,02186 | 3,68% |
| CatBoost | 0,73073 | 0,08105 | 0,08090 | 0,09986 | 0,02112 | 3,56% |

\* Для постоянного скора это артефакт трапецеидальной интерполяции. Подробнее в разделе о дисбалансе.

CatBoost опередил LogReg по ROC-AUC во всех 19 неделях оценки. Среднее
недельное ROC-AUC составило 0,7281 у CatBoost и 0,6570 у LogReg. Средний
прогноз обеих моделей выше наблюдаемой доли дефолтов. Поскольку результаты
этого периода уже просмотрены, для независимой проверки последующих
изменений понадобится новый период оценки.

### Метрики при дисбалансе

Задача бинарная. На оценке 4 449 дефолтов (`target=1`) и 198 896 кейсов
без дефолта (`target=0`). Если всегда присваивать класс 0, accuracy составит
97,81%, полнота по дефолтам — 0%, а ROC-AUC постоянного скора — 0,5.
ROC-AUC оценивает порядок скоров в парах «дефолт и отсутствие дефолта».
Равные скоры дают половину балла.

AP и PR-AUC суммируют кривую «точность–полнота» по положительному классу.
AP взвешивает точность по приросту полноты, а PR-AUC в скрипте использует
трапецеидальное интегрирование. Для постоянного скора AP равна доле
дефолтов (0,02188). Трапецеидальная PR-AUC постоянного скора здесь равна
0,51094 из-за интерполяции до крайней точки кривой с нулевой полнотой
и единичной точностью. Для сравнения с постоянным скором используем AP.

Log loss и Brier оценивают сами вероятности. Log loss сильнее штрафует
уверенные ошибки, Brier усредняет квадрат ошибки вероятности.

### Gini и метрики при пороге 5%

Кейс помечается как рискованный, если прогноз дефолта не ниже 5%.
Порог выбран для иллюстрации. В расчёте использованы исходные вероятности.

| Модель | Gini за весь период | Средняя недельная Gini | Локальная стабильность | Помечено | Найдено дефолтов | Precision | Recall |
|---|---:|---:|---:|---:|---:|---:|---:|
| LogReg | 0,3140 | 0,3140 | 0,29514 | 19845 | 1183 | 5,96% | 26,59% |
| CatBoost | 0,4615 | 0,4562 | 0,43421 | 36124 | 2153 | 5,96% | 48,39% |

Precision — доля дефолтов среди помеченных кейсов. Recall — доля найденных
дефолтов среди всех 4 449 дефолтов на оценке.

Gini равна `2 × ROC-AUC − 1`. На Kaggle итоговый балл учитывает среднюю
недельную Gini, штраф за нисходящий тренд и штраф за разброс относительно
тренда. Локальный расчёт использует 19 недель из размеченного набора.
[Описание метрики соревнования](https://www.kaggle.com/competitions/home-credit-credit-risk-model-stability/overview/evaluation)


## Демонстрация в браузере

После распаковки данных выполните из корня проекта:

```sh
uv sync --locked --group app
uv run --locked --group app train-baselines
uv run --locked --group app streamlit run app/streamlit_app.py
```

Команда обучения сохраняет CatBoost и агрегированные результаты оценки в
`artifacts/scoring.zip`. Для последующих запусков приложения достаточно

- **Оценить заявку.** Заполните синтетический пример или задайте поля вручную.
  Пустые поля передаются как пропуски. Категории показаны в кодировке Home Credit.
- **Качество модели.** Сравните Gini и Gini Stability и измените порог, чтобы
  увидеть precision, recall и число помеченных заявок на отложенном периоде.

Модель возвращает исходную оценку риска. Порог 5% используется для демонстрации.


## Эксперимент с историей заявок

`train_applprev_1_0.parquet` и `train_applprev_1_1.parquet` содержат
предыдущие заявки, связанные с текущим кейсом через `case_id`. Одна строка
`train_base` может иметь несколько строк истории. История внутреннего
источника Home Credit отличается от истории кредитного бюро.

```sh
unzip -n data/raw/home-credit-credit-risk-model-stability.zip 'parquet_files/train/train_applprev_1_*.parquet' -d data/raw
uv run --locked python -m credit_scoring.temporal --output artifacts/temporal-static.csv
uv run --locked python -m credit_scoring.temporal --history --output artifacts/temporal-history.csv
```

Используем только записи с датой создания строго раньше даты текущего решения.
Для каждого кейса считаем число записей за весь доступный период, 30 и 365 дней,
давность последней заявки, среднюю и максимальную суммы. Статусы и причины
отказа требуют отдельной проверки момента доступности. При отсутствии
допустимой истории счётчики равны нулю, давность и суммы остаются пропусками.

Валидация проходит на неделях 24–33, 34–43 и 44–54. Каждая модель обучается
на всех более ранних неделях. Недели 55–72 отведены под калибровку, 73–91
используются для поздней проверки. Горизонт созревания таргета не подтверждён,
поэтому между обучением и валидацией пока нет дополнительного временного зазора.

XGBoost и LightGBM сравниваются с CatBoost на тех же фолдах и 19 признаках.
Для категорий у XGBoost и LightGBM используется one-hot-кодирование,
обучаемое внутри каждого фолда. Сравнение использует по 350 итераций
с фиксированными настройками.

```sh
uv run --locked --group experiments python -m credit_scoring.temporal --history --model XGBoost --output artifacts/temporal-XGBoost.csv
uv run --locked --group experiments python -m credit_scoring.temporal --history --model LightGBM --output artifacts/temporal-LightGBM.csv
uv run --locked --group experiments python -m credit_scoring.calibration artifacts/temporal-{static,history,XGBoost,LightGBM}.csv
```

Вариант для калибровки выбирается по средней Gini Stability трёх фолдов.
После переобучения выбранной модели на неделях 0–54 логистическая
калибровка настраивается на неделях 55–72. Сравнение до и после проводится
на неделях 73–91 по log loss, Brier и метрикам при пороге 5%. Этот поздний
период уже использовался для оценки базовых моделей.

### Результаты временной валидации

| Модель | Признаки | Gini Stability 24–33 | 34–43 | 44–54 | Средняя |
|---|---|---:|---:|---:|---:|
| CatBoost | Статические | 0,3880 | 0,3831 | 0,3919 | 0,3877 |
| CatBoost | Статические и история | 0,4229 | 0,4021 | 0,3734 | **0,3994** |
| XGBoost | Статические и история | 0,4071 | 0,4012 | 0,3066 | 0,3716 |
| LightGBM | Статические и история | 0,4138 | 0,3997 | 0,3555 | 0,3897 |

Из 6 525 979 связанных строк истории использовано 6 381 234.
Исключено 66 записей без даты и 144 679 с датой создания в день решения

### Результат калибровки CatBoost с историей

Доля дефолтов составила 4,25% на неделях калибровки и 2,19% на неделях 73–91. Gini Stability модели с
историей — 0,45857 против 0,43421 у статической модели на том же периоде.
Калибровка сохранила порядок прогнозов и не изменила Gini Stability.

| Вероятности | Средний прогноз | Log loss ↓ | Brier ↓ | Помечено при 5% | Precision | Recall |
|---|---:|---:|---:|---:|---:|---:|
| Исходные | 3,46% | 0,09887 | 0,02106 | 35 860 | 6,14% | 49,52% |
| После калибровки | 3,98% | 0,10120 | 0,02135 | 43 909 | 5,52% | 54,51% |

Калибровка ухудшила обе метрики вероятностей на позднем периоде. На этом
этапе оставляем исходные прогнозы. Streamlit продолжает использовать
статическую модель для ручного ввода.

## Эксперименты со статическими признаками и кредитным бюро

Контрольная модель — CatBoost на 13 статических признаках и шести
агрегатах предыдущих заявок. В каждом эксперименте добавляется один блок
из восьми числовых признаков. Фолды и настройки CatBoost совпадают
с предыдущим сравнением.

- **Расширенная статика.** Признаки из `static_0` по остатку долга,
  просрочкам, входящим платежам и доле платежей с опозданием. Список
  зафиксирован в `src/credit_scoring/feature_experiments.py`.
- **Кредитное бюро.** Для активных и закрытых контрактов отдельно
  используются число подходящих строк, максимальное указанное число
  контрактов, максимум дней просрочки и максимум суммы просрочки.
  Запись допускается, если `lastupdate_1112D` или `lastupdate_388D`
  для соответствующего типа контракта строго раньше даты решения.
  Дата обновления служит приближением момента доступности данных.
  Счётчики строк равны нулю при отсутствии истории, остальные агрегаты
  остаются пропусками.

```sh
unzip -n data/raw/home-credit-credit-risk-model-stability.zip 'parquet_files/train/train_credit_bureau_a_1_*.parquet' -d data/raw
uv run --locked python -m credit_scoring.feature_experiments static
uv run --locked python -m credit_scoring.feature_experiments bureau
```

Отчёты сохраняются в `artifacts/features-static.csv` и
`artifacts/features-bureau.csv`. Приложение использует прежний артефакт.

| CatBoost | Gini Stability 24–33 | 34–43 | 44–54 | Средняя Gini Stability | Средняя недельная Gini |
|---|---:|---:|---:|---:|---:|
| Контроль, 19 признаков | 0,4229 | 0,4021 | 0,3734 | 0,3994 | 0,4272 |
| + расширенная статика | 0,4659 | 0,4535 | 0,4297 | **0,4497** | 0,4730 |
| + кредитное бюро | 0,5090 | 0,2370 | 0,5169 | 0,4210 | **0,5216** |

Расширенная статика улучшила Gini Stability во всех трёх блоках, в среднем
на 0,0502. Бюро улучшило среднюю недельную Gini на каждом фолде, однако
Gini Stability на неделях 34–43 снизилась с 0,4021 до 0,2370.
Покрытие бюро по фолдам составило 86,13%, 85,79% и 88,93%.
Gini внутри сегмента с подходящими записями составила 0,548–0,556,
без подходящих записей — 0,231–0,299. Сегменты различаются по составу,
поэтому разница между ними не измеряет эффект добавления признаков.

По выбранной метрике расширенная статика становится новым ориентиром для
экспериментов. Совместный блок статики и бюро здесь не оценивался.
Прогоны выполнены в локальном окружении с CatBoost 1.2.10.

## Эксперимент со всеми полями `static_0`

Сравниваем CatBoost на 173 входных полях (167 исходных полей `static_0`
и шесть агрегатов предыдущих заявок) с моделью на 27 признаках. Настройки
модели и границы трёх фолдов сохранены. Используются недели 0–54.

```sh
uv run --locked python -m credit_scoring.wide_static
```

Parquet читается батчами. Числовые поля приводятся к `float32` до
конвертации в pandas, а строки категорий хранятся с компактными кодами
и передаются CatBoost как категории. Даты преобразуются в число дней
до текущего решения. Отрицательные интервалы заменяются пропусками.
На обучение передаётся мягкий лимит CatBoost `--ram-limit 2gb`,
который относится к расчёту статистик категорий.

Это разведочный прогон. Для внедрения нужна отдельная проверка времени
доступности параметров выдачи и других полей из широкого набора.
Отчёт по фолдам сохраняется в `artifacts/features-wide-static.csv`.

| CatBoost | 24–33 | 34–43 | 44–54 | Средняя Gini Stability | Средняя недельная Gini |
|---|---:|---:|---:|---:|---:|
| 27 признаков | 0,4659 | 0,4535 | 0,4297 | 0,4497 | 0,4730 |
| 173 поля | 0,5134 | 0,5385 | 0,5324 | **0,5281** | **0,5536** |

Подготовленная таблица из 1 129 770 кейсов занимала 778 МиБ по
`DataFrame.memory_usage`. Прогон занял около 9 минут 54 секунд.
Пиковый RSS не измерен: системная утилита завершилась с ошибкой доступа
к системному параметру после записи отчёта.

### Проверка доступности широкой статики

По словарю Home Credit из 167 исходных полей исключены четыре группы:
условия и события текущей выдачи, показатели дефолта по торговой точке
с неопределённым временем созревания, сводка последней заявки без подтверждённой
даты снимка и межклиентские счётчики без описанной границы времени.
Точный список и причины зафиксированы в `EXCLUDED_BY_REASON`.
Фильтр проверяет чувствительность к спорным полям по их описаниям.
Доступность оставшихся полей в реальном источнике требует подтверждения.

```sh
uv run --locked python -m credit_scoring.wide_static --variant screened
uv run --locked python -m credit_scoring.wide_static --variant screened-bureau
```

Во втором варианте добавляются восемь агрегатов кредитного бюро с прежним
фильтром по дате обновления. В обоих вариантах сохраняются CSV по фолдам
и по неделям. Первый содержит отдельные штрафы Gini Stability за тренд и
разброс, второй — недельную Gini и, для бюро, покрытие. Прогоны выполняются
последовательно, пиковый RSS измеряется средствами Python.

| CatBoost | Полей | Gini Stability 24–33 | 34–43 | 44–54 | Средняя Gini Stability | Средняя недельная Gini | Пик RSS |
|---|---:|---:|---:|---:|---:|---:|---:|
| Полный набор, предыдущий прогон | 173 | 0,5134 | 0,5385 | 0,5324 | 0,5281 | 0,5536 | — |
| После проверки описаний | 112 | 0,3715 | 0,4984 | 0,5132 | 0,4610 | 0,5143 | 1 179 МиБ |
| После проверки + бюро | 120 | 0,4650 | 0,4973 | 0,5554 | 0,5059 | 0,5618 | 1 375 МиБ |

Исключение 61 поля снизило среднюю Gini Stability на 0,0670. Бюро вернуло
0,0448 и дало более высокую среднюю недельную Gini, чем полный набор.
На неделях 34–43 бюро подняло среднюю недельную Gini с 0,5047 до 0,5548.
При этом штраф за нисходящий тренд составил −0,0496, а штраф за разброс
−0,0080. Недельное покрытие бюро на этом фолде колебалось от 82,39% до
91,03%. Само по себе это наблюдение не устанавливает причину тренда.

### Подготовка истории платежей `credit_bureau_a_2`

В первом из 11 файлов проверены пары год–месяц для активных и закрытых
контрактов. Для месяца применены исправления из описания соревнования:
`pmts_month_158T` относится к активному контракту, а `pmts_month_706T`
к закрытому. Из 5 296 008 календарных пар активных контрактов 3 241 483
предшествуют месяцу решения, 195 944 относятся к тому же месяцу и
1 858 581 к более поздним месяцам. Это проверка одной части архива.

Для следующего эксперимента нужно соединить строки с контрактами
`credit_bureau_a_1` по `case_id` и `num_group1`. Фильтр должен требовать
допустимый снимок контракта и месяц платежа строго до месяца решения.

### Эксперимент с помесячной историей платежей
